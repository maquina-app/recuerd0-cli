# recuerd0 v0.9.0

_Released 2026-11-05_

## Fixes

### Stop imports failing on data the stricter API refuses (#11)

The Recuerd0 API got stricter: it refuses repeated and blank versions, enforces size limits,
and normalizes some text on save. `import propose` knew none of this, so it reported a clean
plan, and then `import commit` stopped at the first refusal with nothing after it imported.
The most common trigger was also the most ordinary: a note with a list directly followed by
a code fence. The server adds a blank line between the two on save, commit compared the
read-back byte for byte, and the import stopped with the memory already created.

- **Read-back allows for what the server normalizes.** Commit now accepts the added blank
  line and dropped repeated tags, so those notes import. A row stranded this way by an
  earlier run finishes from its existing ledger.
- **What the API won't take is skipped, and the rest imports.** More than 50 tags, a tag over
  100 characters, content over 1 MB, a null character, invalid UTF-8, a Markdown file emptied
  since its last import, or an export memory with nothing in any version now gets a new
  `unimportable` exception, defaulting to `skip`. An export memory is skipped whole if any
  of its versions is affected. A file emptied since its import keeps its existing text.
- **Repeated and blank export versions are left out.** They hold nothing to keep, so the row
  still creates, flagged `repeated_versions` or `blank_versions` with a detail saying how many
  versions land. An imported memory can therefore end up with fewer versions than its source,
  and different version numbers. Keeping every row would need a server-side exception to the
  rules just added.
- **A row a reviewer sets to `version` fails before any write** if it matches its target or
  would blank it, rather than partway through the commit.

### Stop a refused import row reading as success (#12)

Propose can only predict the limits it knows about, so commit still stops at a refusal it
didn't see coming. Under 0.8.0, what happened next was worse than the stop: a file fixed after
a refusal was left out of the re-run while commit exited 0 with `complete: true`. The import
reported success with a file missing.

The ledger couldn't tell a refusal from a lost response. Both left an intent with nothing
after it, and a lost response may have written to the server, so neither could be replaced.

- **A new `refused` ledger record separates them.** It's written only for the POST's own 4xx,
  so a 404 reading back a successful write can't count as one. A refusal means nothing landed.
- **Recovery now works.** Fix the file and run propose and commit on the same ledger, and it
  imports. Or set the row and its exceptions to `skip` and the rest imports. Leave the file
  alone and propose flags it if it knows the limit. The summary's new `aborted.next` says what
  to do.
- **A row that can't be replaced no longer reads as success.** If an earlier attempt may have
  written part of a row, commit exits 6 with `plan.complete: false` and `rows_left_out` set,
  even when everything else finished, and propose's digest names it under `left_out`.

### Report bad command lines as usage errors (#12)

Everything in this CLI answers in a JSON envelope except its own usage errors, so a script
parsing the output got plain text instead. `memory nope` was worse: it printed help and exited
0, so a typo in a script read as success.

- **A wrong flag, a missing argument or an unknown command is the JSON envelope with exit 2**,
  and the message says how to use the command. Running a command group on its own, like
  `memory`, still prints its help with exit 0.
- **`memory create` with no fields** says what to pass, without calling the server.

### Make `--include inactive` reach the server (#12)

The server accepts `inactive`, but the CLI treated it as an unknown token and returned an empty
list without making a request. `search` now finds memories in archived and deleted workspaces.
`memory list` and `workspace context` return their usual list, since a single workspace has
nothing to add. Any other unknown token still returns an empty list with exit 0.

### Let `--tags ''` clear tags (#12)

An empty value was treated as if the flag hadn't been passed, so there was no way to remove
every tag. On `memory update` and `memory version create`, passing `--tags ''` now clears them.

### Show the server's error message (#11)

Errors were rebuilt from the response's `details`, which is keyed by field for code to read,
so a long title printed `title Title is too long…`. The CLI now shows the server's `message`,
the sentence written for people, and falls back to `details` only when there isn't one.

### Make `memory read tail` work on a title-only memory (#11)

With no lines to read, `tail` asked the server for a range ending at 0, which was refused. It
now returns the memory successfully.

### Say which words a search left out (#11)

The server drops unquoted words under three characters, so a search for `to in` looked like
nothing matched when nothing had been searched. The summary now ends with
`(ignored words under 3 characters: to, in)`.

### Correct the docs and the bundled skill (#11, #12)

`SKILL.md` no longer says CLI search differs from the web app and MCP, since it's now one
contract everywhere, and it gains the link, delete, version and size rules, along with how to
report and recover from a stopped import. `docs/IMPORT.md` said an aborted commit exits 2; a
refused row exits 6.

### Move the Homebrew cask to `postflight_steps`

Homebrew deprecated the cask `postflight` block in favor of declarative install steps, and
GoReleaser 2.19 flags the old form, which failed the release check. The cask still strips the
quarantine attribute from the binary on macOS, and a failure to strip it still doesn't fail
the install.

## Upgrading

No config changes required, but **scripts may see different exit codes**, which is why this is
a minor release:

| Situation | Before | Now |
|---|---|---|
| Wrong flag, missing argument, unknown top-level command | Plain text, exit 1 | JSON envelope, exit 2 |
| Unknown subcommand, like `memory nope` | Help text, exit 0 | JSON envelope, exit 2 |
| `memory create` with no fields | Server's answer | JSON envelope, exit 2, no request |
| Commit leaves out a row it can't safely replace | Exit 0, `complete: true` | Exit 6, `plan.complete: false` |

Treat a non-zero exit or `plan.complete: false` from `import commit` as "something isn't
imported", however much else landed.

- **Ledgers don't go backwards.** Once this build records a refusal, older CLIs can't read that
  ledger, so upgrade everywhere that shares one.
- **A refusal from 0.8.0 or earlier isn't in the ledger.** Run commit once with this build while
  the file is unchanged, and that settles it. If the file has already changed, the row stays
  left out: delete any memory it left, then run propose with a new `--ledger` path.
- **An export an older CLI stopped partway on a repeated or blank version can't resume**,
  because its chain now has a different length. Propose keeps that row on `skip` with a conflict
  exception, the memory stays at the versions that landed, and commit reports it as left out.
  To import it again, use the same delete and new `--ledger` steps.
- **Re-run `import propose` for an export plan made by an older CLI** if it holds repeated or
  blank versions. Its version count no longer matches, so commit refuses it and says so.
- **Homebrew must be 5.1.14 or newer** to load the new cask. `brew update` first if yours is
  older. Other install methods are unaffected.
- **Tooling that parses output:** the import summary and digest gain `rows_left_out`, `left_out`
  and `aborted.next`, error messages now carry the server's wording, and the `search` summary may
  end with the ignored-words note.
- **If you vendored the skill by hand**, re-install it with `recuerd0 skills install` to pick up
  the corrections above.
