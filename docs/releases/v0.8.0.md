# recuerd0 v0.8.0

_Released 2026-09-09_

## Features

### Reach retired memories with `--include obsolete`

The server now treats memories tagged `obsolete`, `superseded` or `deprecated` as retired
knowledge and hides them by default from search, listings, workspace context, stats and
merge candidates. That default is right for everyday retrieval — an agent waking up on a
workspace should not be handed knowledge the workspace has already moved past — but the CLI
had no way to opt out of it. Results came back silently narrowed, with no route to the full
set, while the server's own CLI docs page already advertised `--include obsolete` as if the
flag existed.

- **`--include` on `memory list`, `search` and `workspace context`** — the three commands
  whose endpoints support it. The CLI has no stats or merge-candidates commands, so those
  endpoints get no new surface.
- **`search` reports what it withheld.** The summary gains a `(N obsolete hidden)` note
  drawn from the response's `obsolete_hidden` count, and an `include-obsolete` breadcrumb
  repeats the same query with the flag applied. Without that, a caller auditing retired
  knowledge never learns the memories exist in the first place.
- **An unrecognized token matches nothing.** It returns an empty result set — exit 0, no
  request spent — with a summary naming the token, rather than silently falling back to the
  unwidened list. This deliberately differs from `--category`, which still rejects a bad
  value with exit 2: a bad category is a malformed filter, while a bad include token is a
  well-formed filter that happens to match nothing.
- **Fetch-by-id is never filtered.** `memory show` and `memory read` return a memory
  whether or not it is retired, so they take no `--include`. The contract, including the
  fact that the tag is read from the memory's current version, is documented in the README,
  `docs/API.md` and the bundled agent skill.

## Upgrading

No config changes required.

`--include` is opt-in and defaults to the server's behavior, so every existing command line
returns exactly what it returned before. If you have tooling that parses the `search`
summary string, note that it may now carry a trailing `(N obsolete hidden)` note; the JSON
envelope's shape, exit codes and every other flag are unchanged.
