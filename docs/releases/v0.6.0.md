# recuerd0 v0.6.0

_Released 2026-07-27_

## Features

### Bulk import as propose → review → commit (#1)

Moving an existing body of notes into a workspace meant one memory per command, and any
interruption left the caller guessing which writes had landed. A retry could duplicate
everything already imported, so the safe move was to not retry at all.

Import splits the operation at the review boundary: nothing reaches the server until a
human has read the plan.

- **`import propose` never touches the server.** It scans the source deterministically and
  atomically writes a reviewable `import.plan.yaml`. Re-running it on unchanged input
  produces the same plan.
- **`import commit` executes only what was approved.** Writes are sequential and verified
  by read-back, and an append-only intent/committed ledger records each one before and
  after it happens — so an interrupted run resumes exactly-once rather than restarting.
  Links are applied in a non-fatal second pass, since a bad link should not strip a
  successful import.
- **Two adapters.** Markdown/Obsidian folders (frontmatter, wikilinks, folder→tag mapping)
  and `recuerd0.workspace_export` v1 JSON, which replays version chains faithfully instead
  of flattening them to their latest state.
- **Review happens once.** Plan-wide rules (tag map, exclusions) are edited in the plan;
  per-item exceptions carry defaults. `commit` prints a digest and refuses to proceed
  without `--yes`.
- **Docs.** `docs/IMPORT.md` and a README section; the bundled skill gained an import
  protocol so agents drive the same two-step flow.

No server-side changes — `commit` goes through existing REST endpoints.

### The agent skill ships inside the binary (#2)

The skill that teaches an agent to use recuerd0 was something you had to find and copy,
and every CLI release risked drifting from whatever copy a project had vendored.

- **Embedded with `go:embed`.** Installing the CLI is the whole prerequisite — nothing to
  download, nothing to keep in sync with a release.
- **`recuerd0 skills install`** writes it into a project's skills directory;
  **`recuerd0 skills list`** shows what's bundled.
- **Two files ship:** the skill itself and a conventions reference covering boot, search,
  writing, decisions, map maintenance, and hubs.

## Fixes

### Correct what the skill tells agents to do (#3)

Nothing here changes CLI behavior — it changes what agents are told, which for a skill
amounts to the same thing.

- **A command that doesn't exist.** The skill documented `account switch`; the real
  subcommand is `account select`, so any agent that followed it failed.
- **The binary was misspelled** in the canonical import instruction — `recuerdo` for
  `recuerd0` — across three files *and* the test pinning the string, which made the typo
  the contract.
- **A boot convention that never fired.** Boot was conditional on a `.recuerd0.yaml` that
  no command creates. It now boots from whichever workspace resolves — `--workspace`,
  `RECUERD0_WORKSPACE`, or the file — and offers to write the file when the user names one.
- **Structural memory names** now match the server: *Map — how this workspace is kept* and
  *Index — decisions*.
- **Conventions became opt-out.** The reference defers to a workspace's own recorded
  conventions and imposes nothing where a workspace records none. Previously it carried our
  opinions independently, so deleting the map disabled conventions for MCP users but not CLI
  ones — the escape hatch was real on one surface and cosmetic on the other.

## Upgrading

No config changes required. `import` and `skills` are new command groups; existing commands
are unchanged.

If you vendored the recuerd0 skill by hand, re-install it with `recuerd0 skills install` to
pick up the corrections above — a copy predating this release still names `account switch`.
