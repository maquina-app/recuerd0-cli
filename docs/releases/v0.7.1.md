# recuerd0 v0.7.1

_Released 2026-08-01_

## Fixes

### Survive rate limits during an import commit (#9)

A long `import commit` writes sequentially, one request per memory, and the server rate
limits. A single 429 anywhere in that sequence aborted the run. The ledger made the abort
recoverable — nothing was lost, nothing was written twice — but the operator still had to
notice the failure and re-run, and a large import could hit the same wall again a few
hundred writes later.

- **429s are retried, up to four transport attempts per request.** A bounded integer
  `Retry-After` is honored; without one, the wait falls back to a default. Interactive runs
  show wait progress against the configured attempt count.
- **Request bodies are rebuilt per attempt**, so a retried write sends the same payload
  rather than an already-consumed reader.
- **Only 429 retries.** Network failures, 5xx, and every other error keep the previous
  one-attempt behavior — this is not a general retry policy.
- **Opt out with `RECUERD0_RATE_WAIT=0`**, matched exactly. Any other value leaves waiting
  enabled.

### Stop sibling ledger claims from wedging reconciliation (#9)

Resuming an interrupted commit means reconciling intents whose response was lost: the CLI
looks for a memory that matches the intent and decides whether the write landed. When a
peer memory with the same title had already been claimed by a different ledger path — a
revision, say — that peer was still considered a candidate, and the ambiguity aborted a
resume that had no real ambiguity in it.

Dangling-create reconciliation now excludes memory ids already claimed elsewhere in the
ledger before it classifies candidates. Genuinely unknown peers still abort conservatively;
the conservative default is the point, and it is unchanged.

### Tell the operator how to resume after a failed import (#9)

When a commit aborted, it reported the failure and stopped. The recovery — re-run the same
command, the ledger makes it exactly-once — was documented but not present at the moment it
was needed.

Failed commits now print resume guidance, on stderr and only to a TTY. Machine-readable
stdout envelopes are byte-identical to before. Guidance is suppressed when preparation fails
before a ledger exists, since there is nothing to resume in that case.

## Upgrading

No config changes required. No changes to JSON envelopes, exit codes, plan or ledger
formats, or any command's flags.

Set `RECUERD0_RATE_WAIT=0` if you want the previous fail-fast behavior on rate limits — for
example if an outer supervisor already handles retries and you would rather it see the 429.
