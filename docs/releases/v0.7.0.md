# recuerd0 v0.7.0

_Released 2026-07-29_

## Features

### Import commit writes by default and says what to do next (#6)

`import commit` was a two-mode command that defaulted to the mode nobody wanted. A plain
`commit` printed a plan digest and stopped; the write only happened with `--yes`. The
result was a review step layered on top of a review step — the plan had already been read
before anyone ran `commit` — and a caller who forgot the flag got a success exit code and
an unimported workspace.

- **Commit commits.** The reviewed plan is validated and executed. Interactive runs show
  the create/version counts and the target workspace, then ask once before writing.
- **`--yes` is now a prompt skip, not a mode switch.** It is required when there is no TTY,
  so scripted callers are explicit rather than silently reading a digest. A decline, or a
  plan with nothing to write, exits zero without claiming a write.
- **The dry-run path is gone.** `import propose` is the dry run, and it still never touches
  the server.
- **Envelopes carry guidance.** Propose and commit keep their existing structured `data`
  and add summaries, plan locations where available, and breadcrumbs for reviewing the
  plan, loading workspace context, and running the after-import pass.
- **Workspace naming is best-effort.** A failed workspace lookup no longer blocks an
  otherwise valid import. Commit continues with the workspace id and lets the writes
  return the authoritative authorization or validation error.

### Filter memory list by tag and source (#7)

`memory list` returned everything and left narrowing to the caller, even though the server
already supported both filters. Agents were pulling full lists to find one tagged memory.

- **`--tags`** takes a comma-separated list; **`--source`** takes a single source.
- **Values are URL-escaped**, so tags containing spaces or slashes reach the server intact.

### Account credentials are verified before they are saved (#6)

`account add` wrote whatever it was given. A typo'd token was stored as though it worked
and surfaced later as a confusing failure on an unrelated command.

Credentials are now checked against the API before persistence. `--skip-verify` remains
the escape hatch for adding an account offline or against a server that is not up yet.

### Skill installation reports where it landed (#6)

`skills install` wrote the skill and said little about it, leaving the obvious follow-up
question unanswered: does anything need to load this?

The target directory is now reported in both the JSON envelope and a TTY-only human block,
along with the answer — Claude Code loads the installed skill automatically, and other
agents need `SKILL.md` added to their instructions. Target, collision, force, and overwrite
behavior are unchanged.

## Fixes

### Shared conventions across skill surfaces (#6)

The bundled CLI skill and the public MCP skill carried separate copies of the same policy,
which is a guarantee that they will disagree eventually.

Both now use one operations-based conventions reference. Each interface keeps only its own
commands or tools, while boot, retrieval, writing, decisions, map maintenance, hubs, import
organization, governance, and session capture stay byte-identical across the two
repositories. Workspaces holding only starter content are handled explicitly rather than
falling through the boot path.

## Upgrading

No config changes required.

**`import commit` changed behavior.** If you call it from a script or any non-interactive
context, add `--yes` — without a TTY it now exits with an invalid-args error instead of
printing a digest. If you were relying on bare `commit` as a dry run, use `import propose`,
which is the step that produces the reviewable plan without contacting the server.

If you vendored the recuerd0 skill by hand, re-install it with `recuerd0 skills install` to
pick up the shared conventions reference.
